# ADR: Docker-only restart actor (no watchdog, no systemd units)

Date: `2026-09-09`

## Summary

**Problem:** Plain Compose never restarts an unhealthy container; a healthcheck only labels it (moby #42693/#49161 remain open). The original proposal planned a host-level health watchdog script plus a systemd timer as the restart actor (Work Group 1E).

**Decision:** A5, resolved per the Captain's note (option 1, Docker-only): no host-level watchdog script and no systemd unit/timer files in Phase 1. Container auto-restart and boot persistence rely solely on Docker: `restart: unless-stopped` on every service plus the Docker daemon enabled at boot. A reboot drill (not a watchdog drill) is documented in the first-deployment runbook.

## Context

`depends_on` with `condition: service_healthy` gates STARTUP order only; it neither stops nor restarts the app when Postgres goes unhealthy later. The Docker-only posture accepts this later-failure gap for Phase 1 in exchange for zero extra moving parts; the removed watchdog plan remains documented here as the named upgrade path if a later phase needs later-failure restarts.

## Options Considered

### Option A: Docker restart policies only (chosen, Phase 1)

- Zero extra components; restart on crash, reboot recovery via daemon boot.

### Option B: host watchdog + systemd timer (superseded)

- Covers later-failure (unhealthy-but-running) restarts; requires a script and timer on the host, plus a drill. Revisit only if ever needed.

### Option C: autoheal sidecar (rejected)

- Requires a Docker socket mount in a container; socket is root-equivalent.

## Consequences

- If a container goes unhealthy but keeps running, nothing restarts it in Phase 1; operators rely on `docker compose ps` during the update runbook.
- No systemd unit files exist for the stack; deliberate `docker compose down` stops the stack until manually started, and `unless-stopped` respects that.

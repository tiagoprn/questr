# ADR: Phase 2 staging VM baseline decisions (vmnet, 2 GiB, rename, vault, timers deferral)

Date: `2026-09-10`

## Summary

**Problem:** leanspec change 009 (Phase 2) iterated the `deploy/kvm-host` IaC base (commit `96dc293f`) into the staging VM provisioning system. Five decisions taken during that work need a durable record: network standardization, VM shape, VM naming, secret handling for Tailscale, and the deferred backup-scheduling implementation.

**Decision:**

- **vmnet is the standard questr network; the IaC adjusts to it, never the reverse.** The Makefile lease-query targets (`ssh`, `provision`, `provision-verify`, `status-full`, `baseline`, `baseline-verify`) and all README network references query `vmnet`; the domain in `main.tf` already attached to `vmnet`.
- **VM shape: 2 GiB / 2 vCPU** (`vm_memory_mb` default 4096 -> 2048). The budget is fixed now so the Phase 3 memory retune (`WEB_CONCURRENCY`, `mem_limit`, `maxmemory`) transfers to the intended production target without re-derivation.
- **The VM is renamed `questr-vm` -> `questr-staging` across the whole IaC surface:** libvirt domain name and resource address, cloud-init `local-hostname`/`hostname` and instance-id, Makefile virsh targets and lease greps, destroy script, serial console log path, README, and the SSH key file (`questr_vm_ed25519` -> `questr_staging_ed25519`).
- **Tailscale auth data is handled with ansible-vault (D6):** `ansible/vault/tailscale.yml` (encrypted vars file loaded by `vm-baseline.yml`; path as consolidated by ADR `2026-09-10.ansible-tree-consolidation.md`), vault password file convention `/kvm/questr/vault-password` (unversioned, chmod 600), `no_log: true` on the `tailscale up` task, and a `.example` template tracked in git.
- **Backup/restore scheduling stays deferred to 010 (D5 stands, implementation moves):** the systemd-timers-over-cron decision is locked; the timer units and the 008 runbook cron-wording sync are implemented in Phase 3 with the deployed stack they schedule.

## Context

The base commit provisioned a dev-flavored VM: it queried DHCP leases on the libvirt `default` network while the domain attached to `vmnet` (inconsistent), carried 4 GiB RAM, no Docker, no unattended upgrades, no Tailscale, a debug-stripped `outputs.tf`, and stale `/storage/kvm` path references. Phase 2 closes those gaps so the VM is a repeatable staging target, with the Captain as the executing operator on `enterprise-d`.

The rename affects the OpenTofu resource address (`libvirt_domain.questr_vm` -> `libvirt_domain.questr_staging`). No `moved` block was added: the next apply destroys and recreates the VM, which is exactly what the Phase 2 exit procedure (`make recreate`) does anyway.

## Options Considered

### Option A: standardize on `vmnet`, keep existing base assets (chosen)

- Reuse ladder: extends the working base (Makefile provision pattern, destroy script) instead of inventing a new tree.
- One canonical network name removes a class of lease-query drift between Makefile, README, and future runbooks.

### Option B: rename the network to match the Makefile's `default` queries (rejected)

- Contradicts the Captain's explicit rule; `vmnet` already exists on the host and is referenced elsewhere ( Locust runs on kvm-labs and reaches the VM over Tailscale in Phase 3).

### Option C: Tailscale auth key as a plain (unencrypted) vars file (rejected)

- Secrets must never be committed in plaintext or decryptable without an unversioned password. ansible-vault provides this natively without adding a new tool.

### Option D: keep 4 GiB and retune later (rejected)

- The staging shape is the reference for the production retune; provisioning a larger box would hide memory pressure that Phase 3 limits discovery must see.

## Decision

Adopt A. Implementation details:

- Docker Engine installs from the official apt repository in deb822 format (dist `resolute`) with `daemon.json` log caps 10m x 3 (matching the Phase 1 compose stack), `apt-mark hold` on `docker-ce`/`docker-ce-cli`/`containerd.io`, and security-only unattended-upgrades (no automatic reboots). Engine packages are held so updates never upgrade Docker underneath running containers; applied manually or by a future scheduled task.
- Tailscale installs from its official apt repo and joins the tailnet via `tailscale up --authkey ... --hostname ...` with the key sourced from the vaulted vars file.
- The `ansible.builtin.apt_repository` module is avoided in favor of `deb822_repository` (the former is deprecated in ansible-core 2.25).
- cloud-init drops `rustup` from its package list; the `setup-lang-toolchain` Ansible role remains the single owner of Rust installation.

# ADR: REDIS_PASSWORD in application settings

Date: `2026-09-09`

## Summary

**Problem:** Production Redis uses `requirepass`, but `Settings.REDIS_URL` (`questr/settings.py`) could only produce `redis://<host>:6379/0` with no way to express a password.

**Decision:** Add `REDIS_PASSWORD: str = ''` to `Settings` and make the `REDIS_URL` property password-aware: when `REDIS_PASSWORD` is set, the URL becomes `redis://:<password>@<host>:6379/0`; when empty (the default), the URL is byte-for-byte the old one. This is the only production-code change in change 008 (T5), authorized explicitly by the Captain.

## Context

The dev stack runs Redis without a password, so the empty default is non-breaking for development. The password itself is not stored in code or config files: it comes from the `deploy/secrets/app.env` env_file (gitignored, root-owned 0600 on the VM), generated per `deploy/secrets/README.md`.

## Options Considered

### Option A: password-aware REDIS_URL property (chosen)

- Minimal diff; single source of truth for URL composition; unit-tested.

### Option B: full REDIS_URL env var override

- Moves URL construction out of settings; larger surface; rejected as more mechanism than needed.

## Consequences

- `tests/test_settings.py` covers both branches (with/without password).
- Deployments must keep `REDIS_PASSWORD` in sync with the `redis_password` secret; the mismatch mode (auth error) fails loudly at startup, not silently.

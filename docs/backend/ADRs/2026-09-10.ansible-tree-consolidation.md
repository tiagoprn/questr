# ADR: Consolidate the kvm-host Ansible tree into one shared directory

Date: `2026-09-10`

## Summary

**Problem:** leanspec change 009 delivered two sibling Ansible playbook
directories under `deploy/kvm-host/ansible/` (`setup-lang-toolchain/`,
`vm-baseline/`) whose plumbing was duplicated: byte-identical `ansible.cfg`
(one trailing-newline difference), byte-identical
`callback_plugins/profile_tasks.py` (plus a stray third copy flagged in 009's
review), duplicated `inventory.ini.example` and READMEs. The split existed
only because both playbooks were named `site.yml`, which forces one directory
per playbook in Ansible. Identical configs in two places drift independently.

**Decision:** one shared tree at `deploy/kvm-host/ansible/` with:

- Two top-level entry playbooks named by purpose instead of `site.yml`:
  `setup-lang-toolchain.yml` and `vm-baseline.yml`.
- One shared `ansible.cfg`, one `callback_plugins/`, one
  `inventory.ini.example`, one merged `README.md`.
- A shared `roles/` directory (`rust`, `docker`, `unattended-upgrades`,
  `tailscale`) and the vault files at the shared root (`ansible/vault/`).
- `collections/requirements.yml` at the shared root (where `ansible-galaxy`
  runs from).
- Makefile targets run from `cd ansible` and name the entry playbook.

## Context

The duplication was discovered during leanspec 009's review (the stray
`profile_tasks.py.TO-BE-DELETED` was the only over-engineering finding, net
-68 lines). The consolidation (leanspec change 011) is a pure structural
move: every role task, handler, and file is byte-identical after the move,
verified by a sha256 manifest captured before and compared after (16/16
surviving files OK). Both entry playbooks pass `ansible-playbook
--syntax-check`; runtime behavior on `enterprise-d` is unchanged because all
execution goes through `make` targets from the kvm-host root.

## Options Considered

### Option A: shared tree with two entry playbooks (chosen)

- One copy of the plumbing; roles visible to both playbooks; the stray
  duplicate disappears structurally.
- Entry playbook names document purpose at the call site.

### Option B: keep sibling directories (rejected)

- Preserves the drift risk: identical configs in two places had already
  diverged by a trailing newline and a stale pre-rename inventory example.

### Option C: single playbook with all roles (rejected)

- Couples unrelated workflows (developer toolchains vs staging security
  baseline), entangles the ansible-vault requirement into the toolchain run,
  and mixes `verify` tag semantics between the two jobs.

## Decision

Adopt A. Implementation details:

- Roles, vault, collections, callback plugin, and `ansible.cfg` moved
  unchanged (sha256-verified).
- The stale toolchain inventory example (`lang-vm`, pre-rename naming) was
  discarded; the shared `inventory.ini.example` reflects `questr-staging`.
- The two old READMEs merged into `ansible/README.md` with sections per
  playbook; control-node setup and vault instructions preserved.
- `009/t10-bringup.md` vault-path references updated so the bring-up runbook
  matches the consolidated layout.

## Files changed

- `deploy/kvm-host/ansible/` (consolidated tree: shared plumbing, shared
  `roles/`, `vault/`, `collections/`; entry playbooks
  `setup-lang-toolchain.yml`, `vm-baseline.yml`; merged `README.md`)
- `deploy/kvm-host/Makefile` (four targets repointed to `cd ansible` + entry
  playbook names)
- `deploy/kvm-host/README.md` (playbook path references; the provisioning
  note now lists only the Rust toolchain, matching the playbook trimmed to
  rust/cargo)
- `docs/backend/ADRs/2026-09-10.phase2-staging-vm-baseline.md` (path
  references amended to the consolidated layout)

## Verification

- Pre/post-move sha256 manifest comparison: 16/16 surviving files
  byte-identical (the removed files were exact duplicates or stale content;
  the stray duplicate was eliminated).
- `ansible-playbook --syntax-check setup-lang-toolchain.yml` and
  `ansible-playbook --syntax-check vm-baseline.yml --vault-password-file
  <dummy>` both pass from the shared root.
- grep sweeps: no `site.yml` in the Makefile; no
  `ansible/setup-lang-toolchain/` or `ansible/vm-baseline/` directory
  references in Makefile, docs, or playbooks.
- `make ci` passes.

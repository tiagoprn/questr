# ADR: Suppress ruff F821 and ty unresolved-reference for sandbox scripts

Date: `2026-05-26`

## Summary

An Architecture Decision Record was created to address a lint/type-checker issue with sandbox scripts executed via the shell.

**Problem:** Scripts run by `make shell` receive variables like `session`, `UserORMModel`, and `select` dynamically at runtime via `runpy.run_path()`. Static analysis tools (`ruff`, `ty`) flag these names as undefined.

**Decision:** A static sandbox package was created at `scripts/fast_shell/__init__.py` that re-exports all ORM models and type declarations. The shell injects the runtime session into this module before executing scripts. New sandbox scripts import from `scripts.fast_shell` instead of relying on dynamic globals, making all names resolvable by static analysis tools.

- **ruff:** Zero violations after the change
- **ty:** All checks pass
- **Execution:** Sandbox scripts work correctly

## Context

The `scripts/fast_shell/user_orm_sandbox.py` sandbox script was flagged by both static analysis tools:

- **ruff** produced `F821` (Undefined name) for `UserORMModel` and `session`
- **ty** produced `unresolved-reference` for both names

These variables are dynamically injected at runtime via `runpy.run_path(script_path, init_globals=...)`. No amount of runtime introspection can make static analysis tools aware of dynamically injected globals.

## Options Considered

### Option A: `# noqa: F821` / `# ty: ignore` per-line suppression

- **Pros:** Minimal change
- **Cons:** Fragile — would need repeating on every line for all dynamic variables

### Option B: Static sandbox package with `__init__.py`

Create `scripts/fast_shell/__init__.py` that statically re-exports all ORM models and SQLAlchemy's `select` and `session` type. At runtime, the shell injects the real session into the module before script execution.

- **Pros:**
  - ✅ Both ruff and ty pass globally for ALL scripts in the directory
  - ✅ Uses Python standard import mechanism — transparent to tools
  - ✅ No configuration changes in `pyproject.toml` needed
  - ✅ Scripts become self-documenting (`from scripts.fast_shell import ...`)
  - ✅ Model types follow the ORM chain — fully typed
  - ✅ Future scripts in `scripts/fast_shell/` benefit automatically
- **Cons:**
  - ❌ Requires adding one `from scripts.fast_shell import ...` line to each script
  - ❌ `session` type needs `# ty: ignore` in `__init__.py` to suppress `None` vs `AsyncSession` mismatch

## Decision

Chosen option: **Option B** — Static sandbox package

## Files changed

| File | Change |
|---|---|
| `scripts/fast_shell/__init__.py` | **Created.** Statically imports UserORMModel, EmailVerificationORMModel, AsyncSession, select, session declarations |
| `questr/shell.py` | **Modified.** Injects the real session via `import scripts.fast_shell as _sf; _sf.session = session` before running scripts |
| `scripts/fast_shell/user_orm_sandbox.py` | **Modified.** Now imports from `scripts.fast_shell` instead of relying on dynamic globals |
